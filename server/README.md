# blender rendering server

ブレンダーのレンダリングを行う為のサーバです。
Web上でファイルを指定して、レンダリングを行います。

サーバとして実行した場合、他のマシンで実行することも可能になります。

## Core

一旦Serverを作成し、core部分を分離
Clientを実装する為、必要なことを考える


## Server

Clientからハッシュを受け取り、ハンドシェイクを行う方式
Runnerとして登録して、ClientからのPushを受け付ける

push をできないようにする仕組みを検討する
※hashは再発行できるようにする為、それ以外で考える

## Client

現状、Web実装しているがファイルパスがある為、
Wails実装などを行って指定できるようにすることを目標にする


# 0. Install

release からバイナリを実行する

# 1. Run


```
$ brender-client 
```

# 2. Setting

その端末にあるBlender位置を指定します。

# 3. プロジェクトの作成

プロジェクト＝Blenderファイルのイメージになります。

プロジェクトのサムネイルはデフォルト、シーン指定なし、０フレームで行われます。
ただし、プロジェクト更新で指定して貰えれば変更することが可能です。

アーカイブモードに切り替えると、Blenderファイルをプロジェクトとしてコピーします。
アーカイブモードはサーバレンダリングを行う為の機能で、必ず必要な操作ではありません。

サーバモードでは追加を行えなくする

# 4. ワークスペース

レンダリングするにはワークスペースを作成します。
ワークスペースもシーンの指定ができます。

デフォルトではフレーム等はプロジェクト内の指定のもので行いますが、
シーンやフレームを変更して、レンダリングも可能です。

ワークスペースにはレンダリングの結果が作成されますが、
再度レンダリングした際には必ず上書きされます。
※フレームを変更した場合は元のデータはクリアしない限り残ります。

IDが違うので問題

# サーバとの連携

サーバとの連携を行うと、サーバ上での実行が可能になります。

# サーバ実行時の注意点

blendファイルに対して、依存するファイルを関連付けておいてください。
エラーでわかるようにする予定です。

# サーバを実行

```
$ brender-server -p 80
```

### プロジェクトIDについて

pushを行う時にすでに発行しているプロジェクトIDだった場合を想定しておく
